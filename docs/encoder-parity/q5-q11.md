## Quality 5-11 divergences (`q5-q11` investigator)

**TL;DR (confirmed by experiment):** five independent Rust-side causes explain *every*
q5-q11 bitstream difference on the 17 standard cases in both static and flushed
mode. With the scratch patch (now part of the combined series in
[patches/](patches/)) applied to `vendor/rust-brotli/src`, `brotli_compare --verify --set standard` gives
**238/238 exact at q5-q11** (static and flushed), and q0-q1 stay 17/17. Full
`--verify` (600 configs) still decodes 600/600. q2-q4 and dictionary cases are
unchanged (other investigators cover those).

| # | Cause | Qualities affected | Fix makes exact |
|---|-------|--------------------|-----------------|
| 1 | Missing RLE "hash poisoning" guard in `CreateBackwardReferences` | q5-q9 (alice29, lcet10, three-r128 at q5; alice29/lcet10 at q6-q8) | q5-q8: 17/17 static+flushed |
| 2 | Rust uses its own H9 hasher at q9; C uses H5 (`block_bits=8`, `bucket_bits=15`, 16 distances) | q9 (15/17) | q9: 17/17 (together with #1) |
| 3 | Literal cost estimate uses f32 `log2` (C: double) | q10-q11 command stream (Zopfli) | q10 static: 2 -> 14/17; q11: all command streams identical |
| 4 | Block splitter / clustering / entropy math in f32 (C: double), plus q11 split iterations 3 vs 10 | q10-q11 block splits and context maps | q10/q11 static: 17/17 |
| 5 | Off-by-one in `StitchToPreviousBlockH10` (`i_start` missing `+ 1`) | q10-q11 flushed only | q10/q11 flushed: 17/17 |

Machine: 2x24-core Xeon @2.00GHz (GCE), gcc 15.2 `-O3 -march=native`, Rust
`-C target-cpu=native`. The experiments used a scratch copy of the repo
(LTO off for faster builds; output does not depend on LTO).
Tools: [`scripts/brstruct.py`](../../scripts/brstruct.py) (structural stream
dumper) and scratch static-mode C/Rust drivers (not committed).

**Float precision / FMA:** building C with `-ffp-contract=off` produces
byte-identical output to the default build at q4, q5, q9, q10, q11 on all 17
cases, so FMA contraction is *not* a factor. C's SIMD hasher (H58 at q5-q6,
selected because `BROTLI_TZCNT64` defines `BROTLI_MAX_SIMD_QUALITY`) is
output-equivalent to Rust's H5: after fix #1, q5/q6 match exactly.

---

### 1. RLE hash-poisoning guard missing (q5-q9)

- **Affects:** every quality that uses `CreateBackwardReferences` with a
  multi-entry hasher (q5-q9 here; probably also q2-q4, see that report).
  Observed at q5 on alice29/lcet10/three-r128.min.js and at q6-q8 on
  alice29/lcet10; it shows up only where long, short-period repeats exist
  (e.g. the `*       *       *` separator lines in the Gutenberg texts).
- **First difference:** command stream, not the header. alice29 q5 static:
  only command #1234 differs: C `@9024 ins=1 cpy=44 dist=62`, Rust
  `@9024 ins=1 cpy=53 dist=54`. The streams resync at pos 9133. The previous
  command (#1232) is `ins=6 cpy=46 dist=8`, which is RLE-like. At q6-q8 the
  same spot (`@9028`) is the first diff, and later diffs follow from it.
- **Root cause:** after emitting a copy, C only hashes the last
  `4*distance` positions of copies with `distance < len/4`:
  `c/enc/backward_references_inc.h:271-283`
  (`if (sr.distance < (sr.len >> 2)) range_start = min(range_end, max(range_start, position + sr.len - (sr.distance << 2)));`,
  added in brotli commit a629289, 2017-08 "speedup compression of RLEish
  data"). Rust always stores the full range `position+2 .. position+len`:
  `src/enc/backward_references/mod.rs:2518-2523`. So Rust's buckets hold
  positions inside the RLE run (here pos 8971 = 9025-54), which C never
  inserted. C's best candidate is therefore 44@62.
- **Evidence:** with only this change, q5, q6, q7, q8 are 17/17 exact in
  static and flushed mode (q7/q8 alice29 also had a later same-length/
  different-distance diff @120402; it disappears too, because it was a
  downstream effect of different bucket contents).
- **Fix:** port the 6-line guard (see patch hunk in `backward_references/mod.rs`).
  Size impact is negligible (alice29 q5: C 52809 vs old Rust 52808; lcet10
  133991 vs 133997). It is a perf *win* on RLE-ish data because fewer hashes
  are stored; lcet10 q5 encode went 17.9 -> 18.2 MiB/s in a single rough run.

### 2. q9 hasher choice (Rust H9 vs C H5)

- **Affects:** q9, all inputs except those where both happen to agree
  (monkey, bootstrap).
- **First difference:** command stream (alice29 q9 differs from command #828
  @6149 onward).
- **Root cause:** C `c/enc/quality.h:175-209` (`ChooseHasher`): for q9 with
  `lgwin > 16` and `size_hint < 1MB` it uses type 5 (H5) with
  `block_bits = quality-1 = 8`, `bucket_bits = 15`,
  `num_last_distances_to_check = 16`. Rust `src/enc/encode.rs:845-850`
  special-cases `quality == 9` to type 9, Rust's own `H9` (literal-byte-score
  hasher, `H9_*` constants), which does not exist in C.
- **Evidence:** disabling that branch, so q9 falls through to the H5 path
  (Rust's H5 already uses `block_bits = min(q-1, 9)`, `bucket_bits = 15`, 16
  distances), together with fix #1 makes q9 17/17 exact in static and
  flushed mode.
- **Fix:** remove the `quality == 9` -> H9 branch (or keep H9 behind
  `q9_5`). Size: neutral (lcet10 127431 -> 127437, three-r128 131680 ->
  131685, wiki-Brotli 36271 -> 36268). Perf: mixed in rough single runs
  (lcet10 7.12 -> 7.51 MiB/s, wiki-Brotli 11.14 -> 10.85 MiB/s).
- **Related, suspected (not exercised: all corpora are < 1MB):**
  Rust's H6 condition (`encode.rs:863`, `size_hint > 1<<22` or `q9_5 &&
  > 1<<20`) differs from C's `size_hint >= 1<<20 && lgwin >= 19`.
  Rust's H5 `bucket_bits` adds `&& size_hint <= 1<<20`
  (`encode.rs:880`). Both would diverge for inputs >= 1MB at q5-q9.

### 3. Zopfli literal cost precision (q10-q11 command stream)

- **Affects:** q10 and q11 (all inputs except monkey).
- **First difference:** command stream. alice29 q10: `@32090` C emits
  `ins=0 cpy=5 dist=2411` + `ins=2 cpy=6 dist=137`, Rust emits
  `ins=7 cpy=6 dist=137`. alice29 q11 already differs at `@595`. Block-split
  header differences are downstream of this.
- **Root cause:** `BrotliEstimateBitCostsForLiterals` computes
  `lit_cost = FastLog2(in_window) - FastLog2(histo)` in double. C's
  `FastLog2` returns `double`: the table (`c/enc/fast_log.c:13-14`) holds
  float-precision literals widened to double, and values >= 256 use
  `log2((double)v)` (`c/enc/fast_log.h:51-60`). See
  `c/enc/literal_cost.c:111` (UTF8) and `:164` (non-UTF8). Rust's
  `FastLog2f64` (`src/enc/util.rs:44-58`) returns f32 and computes
  `(v as f32).log2()` for v >= 256, so `in_window_utf8` (up to ~990) and
  `in_window` (up to 4000) lose precision. The result is then rounded to
  float, and the Zopfli DP flips near-ties
  (`src/enc/literal_cost.rs:161-162, 226-227`).
- **Not a factor (ablated):** the prologue formula. C changed it in 2024-11
  (commits cefec3c/1054ecc/782aadd, "Reduce fdiv's into fmul's") to
  `0.35 + (0.35/2000)*i` (`literal_cost.c:105-122`), while Rust keeps
  `0.7 - (2000-i)/2000*0.35` (`literal_cost.rs:168-169`). Keeping Rust's
  formula with fix #3 still gives q10 17/17. Keeping the C formula without
  the double log2 gives only 2/17.
- **Evidence:** adding `FastLog2C(v) -> f64` (f32 table widened for v < 256,
  `(v as f64).log2()` otherwise) and using it in both literal-cost loops:
  q10 static goes from 2/17 to 14/17. q11 goes from 1/17 to 4/17, and all 17
  q11 streams then have *identical command sequences* (remaining diffs are
  header-only, fixed by #4).
- **Fix:** as above. It is cheap, because only the literal-cost loop changes.
  `no_std` needs a libm `log2` or a double table.

### 4. Block splitter / clustering / entropy in f32 (q10-q11 headers)

- **Affects:** q10/q11 block splits (`BTL/BTI/BTD` counts and lengths) and
  literal/distance context maps (clustering). After #3: q10 jquery.min,
  three-r128, wiki-Espresso, and 12 q11 cases. Commands were identical in
  all of them.
- **First difference:** meta-block header, e.g. wiki-Espresso q10
  `BTI n=2` first block length 746 (C) vs 439 (Rust). jquery.min q10:
  `CMAPL[0]` differs in one cluster id.
- **Root cause:** C does all of this math in `double`:
  - `BrotliBitsEntropy` (`c/enc/bit_cost.c:18-40`)
  - `BrotliPopulationCost` (`c/enc/bit_cost_inc.h:12-20,75-80`)
  - `HistogramType::bit_cost_` (`c/enc/histogram_inc.h:15`)
  - `HistogramPair` (`c/enc/cluster.h:23-24`) and `ClusterCostDiff`
    (`c/enc/cluster.c:30-34`)
  - `FindBlocks` `insert_cost`/`cost`/`block_switch_cost`
    (`c/enc/block_splitter_inc.h:66-145`) and `BitCost`
    (`c/enc/block_splitter.c:81-83`)
  - the greedy splitter entropies (`c/enc/metablock.c:474-491,577-581`)
  - `ChooseContextMap`/`ShouldCompress` (`c/enc/encode.c:310,386,476-478`)

  Rust uses `floatX = f32` for all of them:
  - `src/enc/bit_cost.rs:13-34,47-70,76-210`
  - `src/enc/histogram.rs:18,44,71`
  - `src/enc/cluster.rs:17-18,34-38`
  - `src/enc/block_splitter.rs:217-330` (8xf32 SIMD `Mem256f` DP)
  - `src/enc/metablock.rs:312-380`
  - `src/enc/encode.rs:1334-1338,1740,1828`

  Rust also uses the 16-bit log table `FastLog2u16` where C uses
  `FastLog2` (double log2 for v >= 256).

  **Separate discrete difference:** C runs 10 block-split refinement
  iterations at q11 (`block_splitter_inc.h:458`,
  `quality < HQ_ZOPFLIFICATION_QUALITY ? 3 : 10`, with
  `HQ_ZOPFLIFICATION_QUALITY = 11`). Rust's
  `src/enc/block_splitter.rs:796` uses `quality <= 11 ? 3 : 10`, i.e. only
  3 at q11.
- **Latent bug (worth fixing regardless):** `FastLog2u16(p as u16)`
  (`bit_cost.rs:21,26,58,197`) truncates counts >= 65536, which gives a wrong
  log for large histograms (e.g. spaces in a large text block).
- **Evidence:**
  - Converting those Rust modules to f64 with `FastLog2C` (a scalar f64
    `FindBlocks` DP with C's `0.77 + (0.07/2000)*byte_ix` factor;
    `insert_cost` in a `Vec<f64>` in the scratch patch) gives q10 static
    17/17. q11 is then 5/17.
  - Also changing the iteration count to `quality < 11` gives q11 static
    17/17.
  - I did not ablate the f64 changes individually, so the minimal subset is
    unknown. The one-cluster flip in jquery.min suggests that
    `PopulationCost`/`ClusterCostDiff` precision is enough to matter.
- **Fix:** introduce a `costX = f64` type for the bit-cost/cluster/splitter/
  metablock paths, matching C exactly (keep f32 in the Zopfli cost model,
  where C also uses `float`). Thread an `Allocator<f64>` bound, or keep
  `floatX` storage but compute in f64. Also fix the q11 iteration count.
  - Perf (rough, single run, fat LTO, CPU 30): q10 wiki-Brotli 1.10 -> 1.08
    MiB/s, q11 alice29 0.41 -> 0.39 MiB/s. The 10 iterations at q11 and the
    scalar f64 DP cost a few %. A 4xf64 SIMD DP would recover most of it.
  - Size: mixed and small (q10 wiki-Brotli 33593 -> 33696; q11 alice29
    46493 -> 46487). The 10 iterations at q11 are what C ships.

### 5. `StitchToPreviousBlockH10` off-by-one (q10-q11 flushed only)

- **Affects:** q10/q11 flushed (16/17 differ even with #3 and #4). Static is
  unaffected (single block per meta-block input).
- **First difference:** command stream inside a later 4KB meta-block, e.g.
  moment q10 flushed `@43052` (MB19): C `cpy=8 dist=10435` + `cpy=12
  dist=81`, Rust `ins=4 cpy=16 dist=3597`. The context-map difference that
  follows (C `NTREESL=3` vs Rust 1) is downstream.
- **Root cause:** C `c/enc/hash_to_binary_tree_inc.h:307`:
  `i_start = position - MAX_TREE_COMP_LENGTH + 1`. Rust
  `src/enc/backward_references/hq.rs:275` drops the `+ 1`, so on every block
  boundary it re-runs `StoreAndFindMatches` for position `position-128`,
  which was already inserted. That re-roots the binary tree differently and
  changes later matches.
- **Evidence:** adding `+ 1` gives q10/q11 flushed 17/17 (with #3 and #4).
- **Fix:** one-character change. No size or perf impact beyond one fewer
  tree insertion per block.

### Final verification (scratch build with all five fixes)

`brotli_compare --verify` (all sets, q0-11, static + flushed): 600/600 decode
pass. Standard set: q0-q1 17/17, q2-q4 1/17 (unchanged; see `q2-q4`), and
**q5-q11 17/17 in both modes**. Dictionary cases: 0/8 everywhere (unchanged;
see `dictionary`).
